音响与建声团队在装修阶段要反复推算房间的混响时间，判断加多少吸声材料、往哪个频段补吸声才能把回声压下去。目标是一个常驻的房间声学核算后端：它接收房间几何与材料的倍频程吸声数据，回算各频带的混响时间与相关声学量，并能把亥姆霍兹共振吸声器的效果叠加进来。核算只围绕房间声学展开，通过 HTTP 接口供建声工具调用，没有网页界面，也不做用户体系。

内核基于 Sabine 与 Eyring 两套混响模型。房间体积 V 必须为正，总表面积 S = Σ Si；材料在每个倍频程中心频率（至少覆盖 125 到 4000 Hz，中心频率钉死）给出吸声系数 αi，各 αi 必须落在 0 到 1 之间，任一面积不为正、体积不为正、系数越界都要以带原因的错误结构拒收。Sabine 吸声量 A = Σ Si·αi + 4·m·V，其中空气衰减系数 m 在说明里固定为一种取法；Sabine 混响时间 T60,S = 0.161·V / A，系数与声速约定写死，全服务共用同一套常数。Eyring 模型用平均吸声系数 ᾱ = A_surface / S，T60,E = 0.161·V / ( −S·ln(1 − ᾱ) )，符号一旦写反（把分母写成 +S·ln(1 − ᾱ)），高吸声时两套模型会朝相反方向分叉，这正是要重点防住的实现错误。除混响时间外，还要给出临界距离 dc ∝ √(V / T60) 与 Schroeder 频率 f_s ≈ 2000·√(T60 / V)，其中 f_s 必须用本次算出的 T60，不允许另塞一个与混响脱钩的常数。

亥姆霍兹共振吸声器是独立的一块：给定颈口截面积 S_n、颈长 L、腔体容积 V_c 与室温，先算有效颈长 L_eff = L + δ·√(S_n/π)（端部修正 δ 固定为约 1.7 的一种取值），再算共振频率 f0 = (c / 2π)·√( S_n / (V_c·L_eff) )，声速 c 必须与室温取自同一套约定（例如 20°C 对应 343 m/s，声速、波长、f0 三者温度一致）。共振器在其所在频带贡献一份可叠加的附加吸声量（窄带可用洛伦兹型，半宽固定一种），把它加进该频带的总吸声量 A 后重新过一遍混响核算。颈长为负、腔体为零等非法几何同样拒收。

以下跨条件的因果关系是判定正确与否的硬标准，测试要逐条锁住：只增大墙面吸声系数，各频带 T60 应下降，同时临界距离 dc 上升；插入一个调谐到 500 Hz 的共振器后，500 Hz 频带的 T60 必须低于不插入时，而相邻频带受到的影响明显更小；当平均吸声很低（ᾱ 趋近 0）时 Sabine 与 Eyring 的结果彼此接近，吸声很高时 Eyring 应明显短于 Sabine。加装共振器后的曲线必须重新调核算得出，不能在原结果上手工减去几秒。请预置一份教室尺度的示例：中频 Sabine 混响时间应落在零点几秒到两秒的合理量级，任何频带都不得出现负的时间。核算记录要能持久化留痕，多个房间方案同时提交时各自的作业结果互不渗透。

采用 Node.js 20 加 TypeScript，Web 层选 Fastify，把材料与几何校验、Sabine/Eyring 核算、共振器计算、持久化拆成彼此独立的模块，Sabine 与 Eyring 共用同一套物理常数、绝不复制成两份互相改系数的代码。持久化用 PostgreSQL 16。交付一份 Docker 编排，让服务连同数据库能被构建并启动，附带的自动化测试要盯住示例教室的量级、增大吸声后 T60 的单调下降、共振器只压目标频带，以及非法几何与越界系数被拒的行为。
